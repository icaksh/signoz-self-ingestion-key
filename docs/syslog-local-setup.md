# Syslog-over-mTLS Local Setup

The proxy can accept **RFC 5425 syslog over mTLS** on `:6514` and forward each
message (tenant-stamped) to an upstream syslog collector.

## Enable

```bash
SYSLOG_ENABLED=true
SYSLOG_LISTEN_ADDR=:6514
SYSLOG_SERVER_CERT_FILE=/etc/ssl/proxy/server.crt
SYSLOG_SERVER_KEY_FILE=/etc/ssl/proxy/server.key
SYSLOG_CLIENT_CA_FILE=/etc/ssl/proxy/client-ca.crt
SYSLOG_COLLECTOR_ADDR=127.0.0.1:5140  # standalone/local collector
```

For the AIO Docker install, do not use loopback. The bundled collector is reached through Compose DNS:

```bash
SYSLOG_COLLECTOR_ADDR=syslog-collector:5140
```

The bundled collector port is not published to the host.

Optional tuning:

| Variable | Default |
|:---|:---|
| `SYSLOG_MAX_FRAME_BYTES` | `65536` |
| `SYSLOG_MAX_CONNECTIONS` | `1000` |
| `SYSLOG_MAX_CONNS_PER_TENANT` | `50` |
| `SYSLOG_CONN_IDLE_TIMEOUT` | `300s` |

## Authentication

Each client must present a certificate issued (or manually enrolled) for a
tenant. The tenant is resolved by the certificate's SHA-256 fingerprint:

- Unknown fingerprint → connection closed.
- Revoked certificate → connection closed.
- Inactive tenant → connection closed.

Certificates are managed through the admin dashboard (see
[`CA_ENABLEMENT.md`](CA_ENABLEMENT.md)) or enrolled manually by inserting a row
into the `certificates` table.

## Framing

The proxy accepts:

- **Octet-counted framing** (RFC 5425): `<length> <message>`.
- **Newline-delimited framing** as a fallback when the first byte is not a
  digit.

Frames larger than `SYSLOG_MAX_FRAME_BYTES` are rejected before allocation.

The proxy forwards to the local collector using RFC 5425 octet-counted
framing (`<byte-length> <message>`), not newline-delimited framing. This
matters because a message body can legitimately contain a literal newline
(e.g. a multi-line stack trace passed through by rsyslog); newline-delimited
framing would split that into headerless fragments that fail syslog parsing
downstream. The paired collector config (`config/otelcol-syslog.yaml`) sets
`enable_octet_counting: true` on its `syslog.tcp` receiver to match — if you
run a different downstream collector, it must do the same.

## Tenant stamping

Each forwarded message has a tenant structured-data element injected:

```
[tenant@<id> tenant-id="<id>"]
```

Any client-supplied `tenant@…` structured-data ID is stripped first; all other
structured-data IDs are preserved.

The MSG body is also prefixed with `[<tenant.id>][<tenant.name>] ` so tenant
identity is visible directly in the log body text, not only in structured
data (mirrors the OTLP HTTP ingestion path, which prefixes `LogRecord.Body`
the same way).

## Generate test certificates

Use `scripts/gen-test-certs.sh` in the legacy reference (not shipped) or your
own CA to generate a server cert, server key, and client CA bundle for local
testing.

## Local rsyslog client

The bundle generated by the proxy includes `60-signoz.conf` and an idempotent
`install.sh` that installs the certificates and rsyslog config, validates the
rsyslog configuration, and rolls back on failure.
